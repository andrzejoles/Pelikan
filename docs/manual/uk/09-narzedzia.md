# Інструменти

Цей розділ описує інструменти з меню **Інструменти**, **Звіти**, **Проєкт** і **Файл**: порівняння й розгортання змін,
експорт та імпорт, звіти, блокноти, проєкти й файли. Інструменти продуктивності й адміністрування описано в розділі
*План виконання, сеанси й адміністрування*.

## Порівняння схем і розгортання змін

### Порівняння об'єктів користувачів

**Інструменти › Порівняти об'єкти користувачів…** порівнює DDL об'єктів схеми з цільовою схемою — на тому самому або
іншому з'єднанні (напр. `dev_test` з базою приймальних тестів).

![Порівняння об'єктів користувачів](../img/porownanie-obiektow.png)

1. Введіть вихідну схему й натисніть **Завантажити**. Виділіть об'єкти (фільтр типу й назви, **Вибрати видимі**).
2. Виберіть **Цільове з'єднання** й за потреби **Цільова схема**. Налаштуйте параметри: **Ігнорувати регістр**,
   **Ігнорувати пробіли**, **Зберігання** (порівнювати параметри зберігання), **Видалити надлишкові** (скрипт видаляє
   об'єкти, яких немає в джерелі).
3. Натисніть **Порівняти**. Список показує об'єкти лише в джерелі, відмінні й лише в цілі, у порядку залежностей.
4. **Показати відмінності** відкриває переглядач відмінностей, а **Копіювати SQL** і **Відкрити SQL** дають скрипт, що
   вирівнює ціль за джерелом. Скрипт не виконується автоматично — перегляньте його й виконайте свідомо.

### Database Diff і кошик розгортання

**Інструменти › Database Diff…** порівнює схеми за типами об'єктів (також між з'єднаннями); для таблиць генерує `ALTER
TABLE`, що додають, змінюють і видаляють стовпці. Вибрані відмінності додаються кнопкою **До кошика**.

**Інструменти › Кошик розгортання…** збирає об'єкти (DDL) і дані таблиць (з фільтром WHERE) у пакет змін. Об'єкт,
виділений в Object Browser, можна додати через **Інструменти › Кошик › Додати об'єкт до кошика**, а **Кошик › Скрипт
розгортання кошика** генерує скрипт у порядку залежностей у новому SQL Window — з `WHENEVER SQLERROR EXIT` і `COMMIT` у
кінці.

![Скрипт розгортання, згенерований із кошика](../img/koszyk.png)

### Порівняння даних таблиць

**Інструменти › Порівняти дані таблиць…** порівнює дані за первинним ключем (нові, відмінні й надлишкові рядки) з
таблицею в іншій схемі або на іншому з'єднанні. Результат — скрипт або безпосереднє оновлення цілі з `COMMIT` кожні n
рядків.

### Переглядач відмінностей

Усі порівняння тексту (вікно з файлом, об'єкт із базою, локальна історія, **Інструменти › Порівняти файли…**)
використовують вбудований переглядач відмінностей: дві колонки, карта змін, перехід до наступної й попередньої
відмінності, відмінності всередині рядка, ігнорування регістру, пробілів і коментарів, обмін сторін і **Reload**.
Замість нього можна використовувати власну програму — **Налаштування › Інструменти › Зовнішній переглядач відмінностей**
(аргументи `%1`, `%2` — файли, `%3`, `%4` — заголовки).

## Експорт та імпорт

| Інструмент | Для чого |
|---|---|
| Інструменти › Експорт об'єктів користувача… | DDL вибраних об'єктів в один файл (скрипт із «/») або файл на кожен об'єкт — специфікація й тіло пакетів і типів в окремих файлах `.pks`/`.pkb` і `.tps`/`.tpb` (розширення з Налаштувань) без «/», якщо не ввімкнути **Завершувати одиниці знаком /**; **Специфікація й тіло в одному файлі** дає `.pck`/`.typ` із «/»; файли об'єктів містять лише CREATE — привілеї в окремому файлі `назва.grants.sql` або пропущені (**Привілеї у файлах на об'єкт**), вимкнений тригер отримує `DISABLE` у `CREATE TRIGGER`, коментар із датою — лише з **Заголовок із датою експорту**; з параметрами зберігання, у порядку, придатному для виконання |
| Інструменти › Експорт таблиць… | дані таблиць як скрипт INSERT (з DROP/CREATE, TRUNCATE/DELETE, вимкненням тригерів і зовнішніх ключів, COMMIT кожні n, умовою WHERE), у власному (стиснутому) форматі Pelikan або через Data Pump |
| Інструменти › Імпорт таблиць… | імпорт скрипту INSERT або власного формату з вибором таблиць; імпорт Data Pump з REMAP_SCHEMA |
| Інструменти › Text Importer… | файли CSV і текстові: виявлення роздільника, заголовка й кодування, зіставлення полів зі стовпцями, функції перетворення, фільтр, обробка дублікатів, CREATE TABLE з файлу |
| Інструменти › Імпорт з Excel… | файли .xlsx (без Excel і ODBC): аркуш, рядок заголовка, діапазон, зіставлення |
| Інструменти › Майстер імпорту даних… | покроковий майстер для CSV, файлів фіксованої ширини й XLSX, у нову або наявну таблицю, зі збереженням профілю |
| Інструменти › Копіювання схеми… | об'єкти й дані до іншої схеми або з'єднання (таблиці, дані, об'єкти, зовнішні ключі, тригери) |
| Інструменти › Перенесення даних… | таблиця або запит у таблицю на тому самому або іншому з'єднанні, із зіставленням стовпців і режимом додавання / TRUNCATE / DELETE; визначення можна зберегти й запускати у фоні |
| Інструменти › Data Generator… | тестові дані за шаблонами, списками, запитами й наборами (імена, компанії, адреси, e-mail), зі зв'язком master/detail |
| Інструменти › Документація схеми… | HTML-документація: таблиці зі стовпцями й коментарями, ключі, індекси, подання, програми з параметрами |

Експорт Data Pump записує файли на боці сервера (каталог `DATA_PUMP_DIR`), а не на Mac. Інструменти, що записують у
базу, проходять ті самі захисні механізми, що й SQL Window: на продуктивному з'єднанні запитують підтвердження, на
з'єднанні лише для читання — заблоковані. Жодне збережене визначення (перенесення, завдання, імпорту) не містить
паролів.

## Звіти

### Попередньо визначені звіти

**Звіти › Попередньо визначені звіти…** відкриває набір готових звітів про базу в категоріях: *Про базу даних*,
*Об'єкти*, *Таблиці*, *PL/SQL*, *Безпека* та інших. Звіт може показувати сітку, діаграму або вивід DBMS_OUTPUT,
запитувати змінні й мати подробиці рядка. **Відкрити звіт у SQL Window** дає змогу змінити запит, а результат можна
експортувати в CSV, HTML або XLSX.

![Попередньо визначені звіти](../img/raporty-predefiniowane.png)

Меню **Звіти** має також швидкі звіти: **Помилки компіляції**, **Недійсні об'єкти**, **Нещодавно змінені об'єкти**,
**Розміри таблиць**, **Стовпці таблиць**, **Привілеї користувача** і **Сеанси**.

### Власні звіти

1. Відкрийте **Файл › Новий › Report Window** і введіть запит. Змінні (`&<name="…">`, `:назва`, параметри JasperReports)
   працюють так само, як у SQL Window.
2. Виконайте звіт (F8). Результат — HTML-документ.
3. На вкладці **Макет** задайте для стовпців заголовок, вирівнювання, формат чисел (напр. `#,##0.00`) і дат (напр.
   `yyyy-MM-dd`), приховування, **Група** (групування із заголовком групи, master/detail) і **Сума** (суми груп і
   загальна сума).
4. Виберіть **Стиль** із бібліотеки (*Стандартний*, *Зелений*, *Компактний*) і за потреби **Додатковий CSS**; у
   **Параметрах** — заголовок зі змінними (`#title`, `#date`, `#user`, `#connection`, `#змінна`), з'єднання звіту, макет
   форми замість таблиці, нову сторінку після кожної групи й тло.
5. Збережіть звіт як файл `.rep`. **Звіт › Додати звіт до меню Звіти** розміщує його в **Звіти › Мої звіти**.

![Звіт із групами й сумами в стилі «Зелений»](../img/raport-styl.png)

**Звіт › Зберегти звіт як HTML…**, **Експортувати дані звіту…** (CSV, TSV, XML, Excel) і **Друкувати звіт…** (також у
PDF) дають змогу поширити результат. **Заблокувати визначення звіту** приховує запит і макет — звіт тоді можна лише
виконувати (до розблокування).

## Блокнот SQL

Блокнот (**Файл › Новий › Блокнот SQL**) поєднує клітинки SQL/PL/SQL із клітинками Markdown — він добре підходить для
аналізів і покрокових інструкцій.

![Блокнот із клітинкою Markdown, запитом і діаграмою](../img/notatnik.png)

- **Додати клітинку** вставляє клітинку SQL або Markdown; стрілки переміщують клітинки, кошик їх видаляє.
- ▶ виконує клітинку, **Виконати всі** — усі по черзі (зупиняється на помилці).
- Кнопка діаграми створює діаграму з результату клітинки (Pelikan пропонує категорію й ряди).
- Результати й діаграми зберігаються у файлі `.sqlnb`, тож після відкриття їх видно без повторного виконання.
- **Експорт Markdown…** (**Файл › Блокнот › Експортувати блокнот як Markdown…**) зберігає блокнот із результатами як
  документ Markdown.

## Query Builder

**Інструменти › Query Builder…** будує запит візуально: перетягніть таблиці (також синоніми й підзапити), Pelikan
додасть з'єднання за зовнішніми ключами (тип з'єднання можна змінити), виділіть стовпці, задайте псевдоніми, умови WHERE
і HAVING, GROUP BY, ORDER BY і DISTINCT. Запит потрапляє до редактора. Виділений простий SELECT можна відкрити в Query
Builder для зміни.

## Тести багатьох випадків і навантаження

- **Інструменти › Test Manager** — набори тестів (`.pts`): блоки з вхідними й очікуваними значеннями (`=`, `LIKE`, `IN`,
  `NULL`, `NOT NULL`), глобальні змінні, DBMS_OUTPUT і ліміт часу. Зміни, внесені тестами, відкочуються. Тест із
  помилкою можна відкрити в Test Window для налагодження.
- **Інструменти › Тест навантаження…** виконує кроки SQL/PL/SQL у багатьох сеансах паралельно (змінні `:thread` і
  `:iteration`), з результатами в реальному часі (час, помилки, пропускна здатність) і збереженням в Excel.
- **Інструменти › Event Monitor…** отримує в окремому сеансі сповіщення DBMS_ALERT і повідомлення DBMS_PIPE.

## Пошук

- **Редагування › Пошук у редакторах і файлах…** (⌥⇧⌘F) шукає в поточному редакторі, в усіх відкритих вікнах або у
  файлах скриптів у каталогах (типово в розташуваннях переглядача файлів), з урахуванням регістру, цілими словами й
  регулярними виразами. Клацання результату відкриває файл у рядку зі збігом.
- **Інструменти › Знайти об'єкти бази…** (⇧⌘O) шукає код у базі — див. розділ *Object Browser*.
- **Проєкт › Шукати в проєкті…** шукає у файлах, джерелах об'єктів і нотатках проєкту.

## Локальна історія

Pelikan зберігає версію файлу чи об'єкта під час кожного збереження, компіляції, рефакторингу й відновлення — незалежно
від Git і без з'єднання з базою. **Файл › Локальна історія › Локальна історія** показує версії активного вікна;
**Порівняти з поточним** відкриває відмінності, а **Відновити** вставляє стару версію (поточний текст залишається в
історії). **Зберегти версію в історії** додає версію вручну, з описом. Історія зберігає до 50 версій за останні 30 днів.

![Локальна історія файлу](../img/historia-lokalna.png)

## Проєкти, worksets і файли

- **Проєкт** групує файли й об'єкти бази (з нотатками й групами) у файлі `.prj`. **Проєкт › Зібрати проєкт** компілює
  все в порядку елементів, а **Make проєкту** — лише файли, змінені від останнього збирання, і недійсні об'єкти.
  Параметри проєкту — зокрема з'єднання, зупинка після першої помилки й форматування. **Зберегти робочий стіл проєкту**
  запам'ятовує відкриті вікна.
- **Workset** (робочий набір) запам'ятовує відкриті вікна — також із незбереженими змінами й значеннями змінних — і
  відновлює їх під час наступного запуску (**Файл › Workset**: новий, відкрити, зберегти, відновити, закрити, порівняти,
  автозбереження). Макет головного вікна зберігається через **Подання › Зберегти макет вікна**.
- Під час виходу з увімкненим **автозбереженням workset** (типово; **Налаштування › Загальні › Файли › Відновлювати вікна
  після перезапуску** або **Файл › Workset › Автозбереження Workset**) Pelikan не питає про збереження — усі відкриті
  вікна (SQL, програми, тесту, команд, плану, діаграми, нотатника, звіту й консолі з'єднань) повертаються під час
  наступного запуску в тому самому порядку й з тим самим активним вікном. Вікно без файлу повертається зі своїм текстом
  як вікно без файлу, позначене як незбережене.
- **Переглядач файлів** (вкладка **Файли**) показує вибрані каталоги (розташування з фільтром і кольором) із меню:
  відкрити як, перейменувати, новий файл або каталог, перемістити в Смітник, показати у Finder. Фільтр працює за назвою,
  станом, станом Git, розміром і датою.
- **Git**: гілка й стан файлу показуються в рядку стану, у переглядачі файлів і в проєкті. **Інструменти › Git** має
  стан файлу, порівняння з HEAD, `git add`, `git commit` та історію файлу.

## Інше

- **Інструменти › Інструменти користувача…** — власні інструменти: зовнішні програми зі змінними (`#file`, `#object`,
  `#selection`, `#connection`…) або блоки SQL для сеансів. Програми запускаються без оболонки, а змінні ніколи не
  містять паролів.
- **Інструменти › Локальні завдання…** — скрипти, експорти й перенесення даних, що запускаються періодично (кожні n
  хвилин, щодня, у вибрані дні), коли Pelikan працює. Визначення не містять паролів; журнал показує результат кожного
  запуску.
- **Подання › Фонові завдання** — список довгих операцій (Autotrace, експорти, документація) зі станом, часом і
  скасуванням.
- **Інструменти › Документи…** — ваші документи й адреси http(s) зі списку в **Налаштування › Інструменти**.
- Служби macOS (меню **Служби** в будь-якій програмі): **Pelikan: Форматувати SQL** форматує виділений текст на місці, а
  **Pelikan: Відкрити в SQL Window** переносить виділений текст до нового SQL Window Pelikan.

# Безпека і приватність

Цей розділ збирає в одному місці відомості про те, як Pelikan захищає паролі, дані й бази — також від помилок і від
агентів ШІ.

## Паролі

- Паролі баз даних, паролі SSH (тунелі й цілі Pro*C) і паролі ключів SSH зберігаються **виключно у В'язці ключів macOS**
  — у в'язці входу, без синхронізації з iCloud, доступні лише на розблокованому Mac.
- Паролі **ніколи** не потрапляють до файлів Pelikan (визначень з'єднань, налаштувань, worksets), журналів,
  історії команд, аргументів процесів чи змінних середовища. Команди з паролями (`CONNECT`, `ALTER USER … IDENTIFIED
  BY`, `CREATE DATABASE LINK`) не записуються в історію команд.
- Єдиний виняток — лише на ваш явний запит: **Експортувати з'єднання з паролями…** записує паролі у файл
  (зашифровані фразою або відкритим текстом) після підтвердження Touch ID або паролем Mac — див. розділ **З'єднання**,
  «Експорт та імпорт визначень». Агент ШІ не має цієї команди.
- Пароль, не запам'ятований у В'язці ключів, зберігається лише в пам'яті до закриття програми.
- Параметр **Вимагати Touch ID або пароль Mac перед використанням збереженого пароля** (**Налаштування › Oracle › Паролі
  з'єднань**) вимагає підтвердження раз на з'єднання протягом роботи програми — також коли з'єднання використовує агент
  ШІ.
- Пароль SSH потрапляє до програми `ssh` через одноразовий канал, доступний лише вашому обліковому запису, а не через
  аргументи, середовище чи файл.
- Паролі з гаманця Oracle Wallet ніколи не потрапляють до Pelikan — входом займається клієнт Oracle.
- Експорт визначень з'єднань, експорт налаштувань, визначення завдань, перенесень та інструментів користувача, скрипти
  utPLSQL для CI й параметри запуску не містять паролів.

## Захист баз від помилок

- **Середовище з'єднання** (для розробників, тестове, продуктивне) видно за кольором в усьому інтерфейсі.
- На **продуктивному** з'єднанні команди, що змінюють дані чи об'єкти, потребують підтвердження.
- З'єднання **лише для читання** блокує ще до надсилання до бази все, крім запитів (також `SELECT … FOR UPDATE` і блоки
  PL/SQL). Параметр запуску `readonly=` дає змогу відкрити вибрані з'єднання лише для читання на один запуск.
- Pelikan не фіксує транзакцій сам: AutoCommit типово вимкнено, а закриття вікна чи програми з відкритою транзакцією
  завершується запитанням.
- Встановлення utPLSQL із програми працює лише на з'єднаннях для розробників і тестових.
- Інструменти, що генерують скрипти (порівняння, кошик, рефакторинг, DDL подань дуальності, ORDS), відкривають їх у SQL
  Window для перегляду — вони не виконують їх самі.

## Агенти ШІ

Правила роботи агентів описано в розділі *Агенти ШІ*. Коротко:

- агент знає з'єднання лише за назвою й середовищем — він не бачить паролів, хостів, портів, служб чи імен користувачів;
- має власні сеанси бази й не бачить вашої транзакції;
- читає в транзакціях лише для читання, з лімітами;
- зміни виконує лише після вашої згоди у вікні без типової кнопки, а DML залишається незафіксованим до окремої згоди на
  COMMIT;
- не має доступу до консолі SQL*Plus, команд системи, налагоджувача, звітів пакетів Oracle і віддаленої збірки;
- спілкується з Pelikan лише через сокет, доступний вашому обліковому запису, з одноразовим токеном сеансу;
- дані, які прочитає агент, потрапляють до постачальника моделі ШІ — для чутливих даних використовуйте окремого
  користувача бази для агента з обмеженими привілеями й маскування стовпців.

## Що залишає ваш Mac

Pelikan не має телеметрії чи аналітики. Мережеві з'єднання він встановлює лише:

- з базами даних і серверами SSH, які ви налаштуєте;
- з GitHub — раз на день, щоб перевірити оновлення (і завантажити їх, коли ви погодитеся), а також під час встановлення
  utPLSQL із програми (завантаження офіційного випуску);
- у браузері, коли ви самі відкриваєте документацію Oracle (F1), пошук в інтернеті або документ з адресою http(s).

Програми агентів ШІ (Claude Code, Codex, Grok, Antigravity) — незалежні програми постачальників, і вони з'єднуються з
їхніми серверами — надсилають туди те, що агент прочитає в Pelikan.

## Дані на диску

Дані Pelikan зберігаються в каталозі `~/Library/Application Support/Pelikan`: визначення з'єднань (без паролів),
параметри, історія команд, worksets і знімки для відновлення вікон (можуть містити текст незбережених вікон), локальна
історія файлів, звіти, кошики, журнал агентів. Файли із вмістом вікон і журналу зберігаються з правами доступу лише для
вашого облікового запису. Якщо ваш Mac спільний, пам'ятайте, що особа з доступом до вашого облікового запису macOS має
доступ і до цих даних — їх захищають пароль входу до Mac і шифрування диска FileVault.

## Від чого Pelikan не захищає

- Шкідливе програмне забезпечення, що працює у вашому обліковому записі macOS, може читати пам'ять і файли ваших програм
  — це завдання системи (Gatekeeper, XProtect).
- Програма агента, запущена без суворого режиму, має права вашого облікового запису.
- Зафіксовані зміни (COMMIT) і DDL на таблицях скасувати неможливо — Pelikan прямо повідомляє про це перед виконанням.
- Функції, що викликаються в запитах, можуть мати побічні ефекти (напр. автономні транзакції) — їх обмежує лише модель
  привілеїв бази.
